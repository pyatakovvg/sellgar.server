# Design Protocol

## Цель

Собрать достаточно контекста для выбора владельца и проверки, не читая весь
репозиторий.

## Цикл

1. Зафиксировать задачу и scope.
2. Найти workspace-владельца.
3. Открыть ближайший `AGENTS.md`.
4. Проверить текущий код владельца.
5. Найти потребителей, если меняется contract.
6. Сформулировать решение и проверки.

## Decision Gate

Остановиться и согласовать решение, если:

- изменение можно положить в gateway или service;
- нужен новый helper/common слой;
- меняется security/auth/session boundary;
- локальная правка превращается в миграцию нескольких workspace;
- документация и код расходятся.

Сообщение о развилке должно содержать варианты, риски, рекомендуемый вариант и
проверку.

## Design Note

Для широкой задачи зафиксировать:

```text
task:
scope:
owner:
contract:
affected workspaces:
options:
decision:
checks:
```

Для маленькой задачи это может быть короткий рабочий план.
