# Проверки Проектирования

## Перед Реализацией

Понятно:

- какой workspace владеет изменением;
- какой слой меняется;
- меняется ли внешний или внутренний contract;
- какие потребители затронуты;
- какая проверка доказывает результат.

## Architecture Checks

- Gateway не владеет доменным правилом.
- Service не знает gateway-specific HTTP детали.
- Helper не заменяет выбор владельца.
- Каталог отражает ответственность, а не технический прием.
- Module exports минимальны.
- DTO лежит рядом с владельцем входа/операции.
- Auth/session изменения сверены с `services/identity_srv`.

## Когда Остановиться

Остановиться и уточнить решение, если:

- код можно положить в два слоя и оба выглядят правдоподобно;
- хочется создать новый `common/helpers/utils`;
- изменение тянет несколько workspace;
- текущий код противоречит документации;
- нет понятной проверки результата.
