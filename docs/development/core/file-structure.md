# Структура Файлов

Scope: universal baseline.

Сначала определить ответственность файла, потом выбирать каталог.

## Общие Правила

- Каталог нужен, если он обозначает самостоятельную ответственность или
  скрывает несколько файлов одного контракта.
- Каталог не нужен, если он создан "на будущее" или содержит один файл без
  отдельной роли.
- Не создавать технические матрешки вроде `helpers/transport/context`, если
  можно назвать ответственность напрямую.
- Private implementation держать рядом с владельцем сценария.
- Public contract должен быть очевиден из module/package boundary.

## Типовой Каркас

```text
<feature>/
  <feature>.module.ts
  controller/
  service/
  gateway/
  repository/
  dto/
```

Это не шаблон для каждого случая. Использовать только те каталоги, которые
реально нужны.

## Вложенность

Вложенность оправдана, если каждый уровень отвечает на вопрос "чем владеет этот
уровень". Если уровень отвечает только "как технически реализовано", его лучше
убрать или объединить с владельцем.

Плохо:

```text
helpers/session-auth/transport/context/fingerprint.service.ts
```

Лучше:

```text
helpers/session-auth/session-context.service.ts
```

или, если файлов несколько и роль стабильна:

```text
helpers/session-auth/context/
```

## Перенос Кода

При переносе файлов:

- сначала выбрать owner;
- переносить минимально необходимый набор;
- обновить импорты и tests вместе с переносом;
- удалить пустые каталоги;
- запустить локальную проверку workspace.
