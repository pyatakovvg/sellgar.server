# Импорты И Экспорты

Scope: project-specific overlay.

## Общий Порядок

Рекомендуемый порядок групп:

1. внешние пакеты;
2. workspace aliases (`@/api`, `@/common` и т.п.);
3. относительные импорты;
4. типы и DTO рядом с владельцем, если локальный стиль уже так устроен.

Между смысловыми группами оставлять пустую строку.

## Workspace Aliases

Каждый workspace сам задает aliases в своем `tsconfig.json`.

Для `@gateway/admin` сейчас используются:

- `@/api/*` -> `src/api/*`;
- `@/common/*` -> `src/common/*`.

Не добавлять новый alias ради одного спорного импорта. Сначала проверить, не
проще ли оставить относительный путь внутри feature/module boundary.

## Относительные Импорты

Внутри одного feature-каталога относительные импорты нормальны. Они лучше
показывают локальную принадлежность, чем искусственный alias.

Не делать deep import в чужой workspace. Между workspace использовать package
boundary и публичные exports, если они есть.

## Экспорты

NestJS module является основной границей подключения. Не добавлять `index.ts`
там, где repo не использует такую практику.

Public exports должны быть явными. Не использовать `export *` без отдельной
причины.
